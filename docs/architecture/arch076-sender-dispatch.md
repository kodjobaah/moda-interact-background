# ARCH-076 outbound sender authority

Recovery ownership remains the immutable Conversation assignment. Initial Shopify and Woo outreach, follow-ups, AI responses and HUMAN commands obtain the exact WABA/phone pair at the final SQL provider permit. Draining inventory does not move existing assignments. A missing/released assignment never falls back to the configured singleton for new recovery outreach.

`dispatch-sender.ts` captures the validated, unsealed `messaging.sender` configuration outside SQL. Inside the existing owner-locked final permit it checks the actual configuration row/version under `FOR SHARE`, then the assignment, recipient, open route/thread and verified sender. The existing consent, STOP, window, control, template and funding checks remain independently authoritative. The root message stores the pair together with its irreversible permit; ordered parts must match that same frozen pair. Transport uses the permitted phone and current credentials for that WABA. It cannot choose another phone or account on retry.

Non-pooled Conversation sends take Admin's exact `whatsapp-pool-membership:<phone>` advisory key before configuration/inventory locks and refuse any inventory row, including disabled inventory. This serializes enrollment preflight with new durable standalone permits. No provider, Redis or model call occurs inside that transaction.

The explicitly approved legacy-history exception permits only an already-owned, in-window AGENT/HUMAN freeform continuation of an unassigned recovery. It requires exact confirmed root sender proof linked to the sent initial attempt's frozen recipient, or the frozen multipart sender/recipient plus an acknowledged admitted part. The proved pair must match the current singleton and remain unenrolled under the membership fence. A current mutable phone/configuration, unknown send or NULL pair without a durable witness grants nothing. No assignment is manufactured or history migrated; new initial/proactive sends are excluded.

Scalar status processing rejects a foreign stamped WABA/phone before lifecycle changes. Post-commit compensation, contact reachability and merchant notices require the verified owned status transaction; a refused event cannot trigger those effects. Matching duplicate events retain existing idempotent repair behavior. Existing uncertain provider outcomes are never made resendable by timeouts or cutover.
