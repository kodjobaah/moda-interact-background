# Recovery outbound checkout footer coverage

New eligible freeform bodies use the trusted, current tenant/recovery checkout URL and a language-neutral `──────────` divider. Composition happens before freezing, moderation, hashing, delivery planning and final permit admission. The provider receives the same committed body; it never appends a footer.

| Send class | Preparation and boundary |
| --- | --- |
| AI conversational text/image | Conversation wrapper preparation, then existing text/caption planning; overlong captions retain full text fallback. |
| HUMAN takeover, configured wrapper or passthrough | Wrapper preparation plus explicit URL receipt in immutable prepared-command evidence; original staff text remains verbatim. |
| Known-recovery terminal/final freeform notice from text or template admission | Trusted context resolution before preparation/moderation; provider uses the prepared complete notice. |
| Audio/transcription failure notice | Explicit server-owned unfrozen-notice flag through local admission; trusted context preparation before moderation. |
| Oversized current-message clarification | The same explicit local preparation flag; ordinary frozen AI replies are not recomposed. |
| Successful approved initial/follow-up Meta template | Approved payload unchanged; existing approved checkout parameter remains the link mechanism. No appended freeform divider. |
| Unbound routing guidance/general conversation | No recovery basket can be inferred; no recovery URL added. |
| STOP, blocked, consent/security prohibitions | Existing no-send/control rules remain authoritative; no footer can authorize a send. |
| Missing/expired checkout | Existing controlled no-URL behavior; no invented link. Tenant/context mismatch or invalid eligible URL refuses preparation. |

AI preparation canonicalizes standalone exact trusted links while preserving localized labels and unrelated links. HUMAN preparation is append-only: authored occurrences of a URL remain verbatim, so an authored URL may also appear above the single canonical footer block. This protects staff authorship rather than rewriting their message.

Legacy frozen human commands and AI applications replay their original bytes, including no-divider footers. New workers understand both evidence generations. Old workers do not understand augmented HUMAN passthrough evidence: drain and replace old messaging workers before accepting new HUMAN commands with the new footer. Do not rewrite old commands or delivered messages during rollout.

The optional expected-content final SQL fence refuses an automated notice whose persisted body changed after preparation. Legacy callers omitting that option and initial/template/media protections retain their previous semantics. No database schema, published Shared contract or retry policy changes are required.
