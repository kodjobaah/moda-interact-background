# ARCH-043 — Background operational policy cutover

The canonical keys are `woo.couponSync` and `speech.transcription`. Support-message translation **does not** use `support.translation` and never reads a provider/model override environment variable when creating a new batch. An enabled automatic default in `CommerceTranslationModelConfiguration` (in the trusted Commerce deployment environment) is required. Compare any historical support-translation model with the automatic default and obtain operator approval before switching if the result changes. Already created batches keep their persisted `provider`/`model`; pricing and store-category flows are unchanged. Translation provider credential use is owned by BACKGROUND-009.

- **Woo dispatch**: the globally leased dispatch loop reads one complete `woo.couponSync` policy at the beginning of each leased cycle, and constructs a fresh dispatcher. It does not query per shop, page or coupon. Missing rows use the bounded ARCH-036 defaults. Disabled/invalid rows or database outage fail that cycle without falling back to environment overrides.
- **Woo scan**: each BullMQ coupon job reads one policy and passes it into the catalogue, page-reader and HTTP transport. A scan's limits do not change partway through provider I/O or database transactions. Missing rows use the same bounded defaults. Failures are retryable job errors under the existing queue policy; they cannot weaken any existing lease, claim or generation fence.
- **Worker concurrency**: `workerConcurrency` is read before creating the BullMQ worker and remains fixed for that worker's lifetime; changing it requires a planned restart/redeploy of each worker replica, not creating an additional consumer in-process. The existing global lease prevents competing dispatch reservations. The worker must not attempt a live concurrency change or spawn a second consumer.
- **Speech**: each transcription operation loads one validated `speech.transcription` policy. Missing rows preserve the existing bounded provider/model defaults. Invalid/disabled/unavailable configuration fails before provider I/O; API credentials still use their existing external source until BACKGROUND-009. No configuration read is added to unrelated turns or webhooks.
- **Cutover**: before rollout ensure the Admin writer supplies the strict ten-field Woo JSON and the strict three-field speech JSON. The operational reader uses deployment identity, not request-supplied environment. Compare old effective values before rollout; an explicit policy change can alter dispatch timings/model outcomes. `BackgroundRuntimeConfig` remains authoritative for lease cadence, unrelated queue concurrency, and other existing operational controls. There is no policy cache and no last-known-good fallback.

This patch does not deploy migrations, update Admin, publish secrets, or implement BACKGROUND-002/009. Run focused tests, repository typecheck/build, and disposable PostgreSQL validation before task acceptance.
